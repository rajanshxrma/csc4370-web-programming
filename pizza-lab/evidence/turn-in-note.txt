My two sentences:
1. The name attribute is the key PHP gets in $_POST (name="quantity" turns into $_POST['quantity']), while the id only exists in the browser so the label can point at the control, so an input with an id but no name never sends anything to the server.
2. A checkbox that isn't checked is left out of the request completely, not sent as an empty value, which is why order.php defaults $_POST['toppings'] to [] and why the boxes are named toppings[] so PHP collects the checked ones into an array instead of keeping only the last one.

Critical thinking (one request, one invalid value):
I reject the whole request. The browser checks (required, min/max, the fixed list of checkboxes) only help the person typing, anyone can change them in DevTools or send the request with curl, so the PHP checks are the only ones that count. A topping my form never offered can't come from a real submission, so either someone is messing with the request or they're on an old menu, and either way I don't actually know what they wanted. If I quietly dropped "unicorn" and accepted the rest, the ticket would not match what the person thinks they ordered and I'd be keeping data that only passed by accident. Sending back a 422 with a clear list of what was wrong costs them one resubmit and they see exactly what happened instead of a ticket that silently changed. Accepting the valid parts would be fine for something low stakes like optional analytics, but not for an order where every field matters.
